# 独立 AI 工具审批

`AgentToolApproval.evaluate(_:review:)` 先检查硬性规则，再通过调用方提供的独立、无工具模型请求审批。返回值仅是审批结论，不会执行命令。`Request` 包含一次性 id、实际工具名、原始命令、用户意图、服务器上下文及模式。模型必须返回绑定相同 id 的严格 JSON。

初始安全范围有意保守：少量明确的只读命令及已知选项可进入 AI 审批；standard 模式另允许 `/tmp` 或 `/var/tmp` 下创建目录。读操作也须经过 AI 判断是否涉及隐私、超出用户任务或存在路径风险。此规则不尝试证明远端文件系统或 shell 环境可信，调用方只能用于已建立信任的执行环境；AI 无法确定目标范围时必须转人工。

删除/覆盖、权限/账户、服务/生产变更、软件执行安装、网络传输、凭据、未识别命令/选项、复合 shell、重定向、变量替换等均转人工。模型不能覆盖硬性规则。返回无效 JSON、不同 id、异常、取消或不明确的结论时不批准。

宿主必须：

- 为 review 单独请求模型，禁用所有工具，设置总超时和输出大小限制。
- 执行前重新验证会话、连接、模式、原始工具参数及 pending 状态没有变化。
- 将批准/人工确认原因展示并记录；保留人工运行和跳过入口。
- 会话切换、连接变更、人工执行/跳过时取消尚未完成的审批。
- 不缓存可供其他命令、会话或机器复用的批准结论。

uTerm 的聊天 Agent 和并行 AI 后续命令均使用此入口。审批复用当前 provider/model，但使用独立上下文，只有用户任务和必要服务器上下文，不接收执行 Agent 的审批指令。20 秒总超时、8 KiB 输出上限、工具事件拒绝由宿主实现。每步确认模式完全不调用审批模型。并行执行遇到需人工确认的命令时停止该服务器后续自动步骤，在结果中显示命令及原因。

本地开发用 workspace 覆盖 uAppKit（见 README「本地开发」）。发布仍需发布 uAppKit 版本并更新消费方的远程依赖；不要将本地 workspace 验证当作远程 tag 已发布的证据。
